# ContextGuard

## Authority and provenance
The user's detailed product/implementation brief explicitly supersedes the earlier draft and authorizes local implementation. This records written direction, not a retrospective interview. No earlier application or Synora code, schema, prompts or UI is copied.

## The Unique Kernel
Check whether selected evidence is complete, consistent and reliable enough for a specific goal. Link material findings to exact passages and retain human clarification and decision history. Models propose interpretations; code enforces permissions, routing, identity and citations.

## Who It's For
Project owners and identifiable team members deciding whether a particular action has sufficient reliable context.

## The Core Loop
Authorized capture/upload → interpret the complete conversation → extract project evidence → discard confidently unrelated content → generate project reviews → filter and inspect findings → assign/respond/confirm → update decisions → export the report or a consolidated document. See [the current direction and implementation boundary](../docs/conversation-first-plan.md). The conversation-first flow is implemented with controlled/browser verification; live matching accuracy remains separately unverified.

## Inspiration & Identity
Local Windows, minimal solid paper/slate/cobalt UI, square components, no gradients or decorative shadows, brief guide sentences. Synora informs only the high-level adapter/shared-context/routing pattern. Current direction: Sources handles connections/capture, Project Reviews handles project content and findings, and unmatched content is omitted and removed from active input after successful processing. The registration panel and Unknown Context tab are removed.

## Why This Matters to the Learner
A repeatable plan-first workflow and a working, reviewed and tested application. The learner supplied the current direction and delegated implementation decisions.

## What "Working" Looks Like
Unknown evidence cannot read or enter project memory. Confirmed routing allows a goal-specific review with verified passages. A review owner assigns a finding; an accountable person responds; a decision owner confirms. A later contradictory statement creates an open linked finding while preserving the old decision. Other projects/workspaces cannot access it. Fictional/test behavior is labeled; live accounts are verified separately.

## The POC Boundary
Manual TXT/MD/PDF/DOCX, Vexa transcript client, Slack OAuth/selected pulls, isolated experimental read-only Baileys pairing/selected-text adapter with manual-import fallback, common evidence format, source permissions, validated conversation routing/disposal, team identities/roles, versioned decisions, Muse Wonder/Groq/NVIDIA provider interface, exact citations, review filtering and Word/Markdown reports/documents. Source connectors and teams are now in scope; earlier deferrals are superseded. The broad scope exceeds an afternoon exercise and requires incremental verification.

Processing visibility is part of the core loop: show upload immediately, then real matching and analysis stages, completion or retained-input retry. Counters describe their own stage; there is no invented overall percentage. Model/network failures never become fabricated results. The current six-document live run remains unsuccessful, despite historical provider-only successes.

## Later
Enterprise SSO, hosted multi-instance deployment, unattended ingestion and production connector certification. Actual integration acceptance requires real consented accounts, not mocks.

## Explicitly Cut
Silent meeting joins, duplicate STT, WhatsApp sending/replies/bulk scraping, automatic truth or authority selection, silent cross-project duplication, unexplained numerical readiness scores, silent data transfer/deployment/publication and claims that test adapters are live integrations.
