Three actual code stops

  1. app/service.py: Service.ingest / route / segment enforces source/project permissions and explicit or approved routing. Unknown items stay unassigned; source grants do not grant project access.
  2. app/review.py: Reviews.analyze / verified / current snapshots the goal and selected evidence, checks exact quotes and comparison boundaries, and rejects stale original/segment evidence.
  3. app/review.py: Reviews.respond / confirm / brief records actor/time, separates response from authority, appends a decision and exports the stored report.
Why one concrete test matters

“Source access must not override project access” becomes a regression test in tests/test_additional_boundaries.py: test_source_grant_cannot_read_or_revise_an_inaccessible_project. It exposed a real revision-path bug. Reusable practice: turn a broad permission rule into a specific forbidden operation, then test that operation.
