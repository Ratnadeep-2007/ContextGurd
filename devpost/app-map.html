Follow the action

  1. frontend/src/components/Report.tsx, FindingDetail and its save function: the owner field comes first. One dropdown offers a contextual answer; Other opens a textbox. Saving sends the selected choice ID or custom answer, owner, action and current case version.
  2. backend/app/main.py, resolve: the server checks that the choice belongs to this finding and that its action matches. It records the exact answer, source snapshot, owner and input fingerprint through Store.save, then starts a review run. The source documents are preserved.
  3. backend/app/workflow.py, verify and brief: verified evidence supports findings; only a matching current-input resolution changes its status. The browser renders the result. Prepare brief groups recorded clarifications, remaining questions and risks with their sources and owners.
Where project memory fits

backend/app/project_memory.py derives historical confirmed decisions from the exact local records. Store._refresh_memory updates the project index with the case transaction. A later review assigned to the same project can recall those answers. They remain historical user statements, not automatic approval of new evidence. The optional Mem0 REST service is not connected in the recorded environment.

To change this, start here

  • Owner/answer order: frontend/src/components/Report.tsx, FindingDetail.
  • Dropdown and Other textbox: frontend/src/components/ClarificationAnswer.tsx.
  • Which choices are valid and how pending/risk choices behave: backend/app/workflow.py, clarification_choices; validation in main.py, resolve.
  • Quotes, IDs and conflict support: backend/app/workflow.py, verify.
  • Sample content: backend/app/sample.py or samples/synora-three-docs/.
  • Evidence for this UI contract: scripts/browser-clarification-check.mjs and backend/tests/test_clarification_options.py.

A practice to reuse

The learner supplied a precise UI requirement: owner first, one context-based dropdown, Other last, and a textbox only for Other. The browser check now asserts that order, a single select, the final option, conditional text, saved provenance and restored state after reload. Turning a request into observable behavior makes it possible to detect a mismatch and verify the correction.

A separate source check rejects invented or empty normalized quotations. An exact quotation establishes that the words exist in the source; it does not establish their truth or interpretation.
